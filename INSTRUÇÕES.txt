🏆 CONFORMIDADE SOLID GARANTIDA:

✓ [S] Single Responsibility Principle
  └─ Cada classe tem UMA responsabilidade clara
  └─ Ex: Pagamento gerencia APENAS estado de pagamento

✓ [O] Open/Closed Principle
  └─ Aberto para extensão (novos métodos de pagamento)
  └─ Fechado para modificação (nenhuma classe precisa ser modificada)
  └─ Ex: Adicionar PagamentoApplePay SEM modificar nada!

✓ [L] Liskov Substitution Principle
  └─ Todas as implementações cumprem contrato
  └─ SEM UnsupportedOperationException ou exceções inesperadas
  └─ Qualquer ProcessadorPagamento pode substituir outro

✓ [I] Interface Segregation Principle
  └─ Interfaces pequenas (1-3 métodos) e específicas
  └─ ProcessadorPagamento: 2 métodos
  └─ CanalNotificacao: 4 métodos
  └─ RepositorioPedidos: 3 métodos
  └─ Ninguém é forçado a depender de métodos não utilizados

✓ [D] Dependency Inversion Principle
  └─ Alto-nível depende de abstrações (interfaces)
  └─ Injeção manual de dependências via construtor
  └─ PROIBIDO: Usar 'new' dentro dos serviços
  └─ OrquestradorPedidos recebe tudo via construtor

🔌 COMO ADICIONAR NOVO MÉTODO DE PAGAMENTO:

1. Criar nova classe:
   
   public class PagamentoTransferencia implements ProcessadorPagamento {
       @Override
       public boolean processar(Pagamento pagamento) {
           // Sua implementação aqui
           pagamento.marcarComoaprovado("TRF-123456");
           return true;
       }
       
       @Override
       public String obterMetodoPagamento() {
           return "Transferência Bancária";
       }
   }

2. Usar no Main:
   
   ProcessadorPagamento processador = new PagamentoTransferencia();
   ServicoPagamento servico = new ServicoPagamento(processador);
   orquestrador.executarCheckout(pedido, servico);
